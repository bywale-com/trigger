## What the factory actually does

Read at `bywale-com/omcoda_tower` `cursor/factory-agents-scope-33ee` `0bad2c30747c3c52894df345f65487a0cf42395b`, ledger revision 61.

The implementation-packet template’s `## Plates` line is: “None, or the five buckets. Do not invent a plate when the glass does not change.” `docs/factory/OPERATING-PROTOCOL.md` says: when a packet changes the glass, the plate is a screenshot of `/prototype-ant` with only the new hole painted, read with the five buckets in `docs/register/PLATE-READ.md` — copy, do not build, implied, completes, out of scope. PKT-001 changes no glass and has no plate. That `PLATE-READ.md` is not on this factory SHA; the five names are on the operating protocol and in Travis `docs/register/PLATE-READ.md` at `a47becf`. Do not invent a thirteenth bucket.

Live packet notes on this SHA: PKT-001 has no `## Plates` section. PKT-002 through PKT-009 say `## Plates` / `None.` Packet manifests have no `plates` field. The recursive git tree has no image under `docs/factory`. Product screenshots that may live under `docs/register` or blueprint folders are not packet plates. Trigger must not discover those.

Discovery is therefore the packet note plus a scoped directory listing on the observed SHA. A committed image on that SHA is enough. Stage, wake, release, engineering, and merge to `main` are not gates.

## Face

The header, table, graph, filters, and packet 002 sections stay as they are.

On the **packet** page, after Intended behavior and before Verification, when there is something to show:

1. **Plates.** Each discovered image, in markdown order then directory order for files the note did not name. The `img` `src` is the GitHub raw URL for that path at the observed SHA. Under the image, the repo path is a link to the GitHub blob URL at that same SHA. That blob is the authoritative artifact. Trigger does not proxy the bytes and does not put PNG bytes on the snapshot.
2. **Five-bucket read.** Copy, Do not build, Implied, Completes, Out of scope. The text is the `## Plates` body of that packet note. Missing buckets say `unavailable`. Do not invent copy.
3. **Several images** on one packet are several images, not a carousel and not a gallery product.

When the note says `None.` and the scoped directories have no image for that packet, omit the Plates section entirely. The fixture packet `pkt-001-click-attribution` at `9c45f19` has no plate; its page must not grow a Plates heading.

The initiative page does not grow a Plates section. Packet plates belong to packets.

There is no Approve, Reject, Release, or “wait for engineering” control. A draft packet on the factory branch that has a committed plate shows that plate.

Failed Tower read still keeps the last snapshot. A missing image URL is a broken `img`, not a guessed picture.

## Discovery rules

Copy these. Do not soften them.

1. Read `## Plates` on the packet note already fetched for intended behavior. Markdown `![alt](path)` and `<img src>` whose target resolves inside `docs/factory/` are plates. Relative paths resolve from the note’s directory.
2. List only these directories, and only names that are `png` / `webp` / `jpg` / `jpeg` / `gif`:
   - `docs/factory/initiatives/<initiativeId>/plates/`
   - `docs/factory/initiatives/<initiativeId>/packets/plates/`
   - `docs/factory/initiatives/<initiativeId>/packets/<packetId>/` in both `pkt-` and `PKT-` forms
   - files in the packets directory whose names include that packet’s id (`pkt-` or `PKT-`)
3. A file in a packet-specific subdirectory belongs to that packet even if the filename omits the id. A file in a shared `plates/` directory belongs to the packet only when the filename includes the packet id.
4. A committed file wins over the word `None.` The images show. Buckets stay unavailable unless the note also filled them.
5. Do not walk `docs/register`, blueprint folders, or the whole repository. Do not treat Trigger’s own `docs/register/plates/v1/` as Tower plates.

## Named for the Systems Analyst

The ledger remains the record of production state. Plates are files on the same tree the desk already reads. There is no plates table. GitHub Contents is a directory listing for the GitHub read mode the Vercel plant already uses; git `readdir` is the local listing. Raw and blob URLs are constructed from `repo`, observed `sha`, and path. Bytes stay at GitHub.

`TOWER_REF` / `source.json` stay the factory source. A plate appears when that ref’s commit contains it.
